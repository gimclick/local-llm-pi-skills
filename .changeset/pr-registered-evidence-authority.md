`pr` is now registered in this fork's `pi.skills` manifest, as the twelfth skill. It stays model-invoked, unchanged in its invocation metadata: no `disable-model-invocation` in frontmatter and no `policy` block in `agents/openai.yaml`, the same shape as the other model-invoked skills here, so Pi advertises it by name, description and path in the agent's `<available_skills>` block, loads it by reading its `SKILL.md` (Pi has no Skill tool), and the human can force it with `/skill:pr`. The frontmatter `description` was widened from "Use when writing a PR body." to carry the trigger phrasing Pi routes on: a PR description or reviewer summary, before/after evidence for a change, and how risky a branch is to merge. That is the only metadata change. The Claude plugin manifest is untouched: the promoted set stays 27.

The upstream methodology is preserved and the template survives whole. The three-section body (**Summary**, **Evidence**, **Merge Danger**) in that order, the six Summary views and the rule to pick the smallest one that makes the point clear, the placement guidance, the `GLOSSARY.md` line that asks for the user's domain language, the before/after evidence tiers with screenshots S-tier and execution-based evidence A-tier, the one-way or two-way door definition, and the blast-radius definition are upstream's, word for word. `CREDITS.md` and the attribution to Dex Horthy's `show-me` are untouched.

What this fork adds is input authority, not a workflow. A short **Inputs and authority** section sits between the template and the section guidance. It pins the comparison the body describes as fixed-point and head SHAs rather than a moving branch name, and names that range in the draft so a reviewer can check it. It prefers observed evidence over description, quoting test output, the committed spec or ticket, and recorded Code Review findings rather than restating them. It keeps observed, claimed, and assumed apart, so "the tests pass" with no run beside it is a claim rather than evidence. It includes every commit inside the described range, including corrections made after a review, and labels which part is a correction. It forbids inventing test results, screenshots, review findings, or rollback guarantees, and asks for evidence a section asks for that is unavailable to be named as missing rather than filled with a plausible result. It states that the skill writes the body and nothing else: no push, no pull request opened or edited, no commit, no issue touched, and publication remains a separately authorized action.

Two clarifications land inside the sections they govern, both additive. Under **Evidence**: name the command beside the output, and where only a passing run exists say so, because a green run on its own is a claim about the change and not a before and after. Under **Merge Danger**: the door call and the blast radius are an assessment, not facts the diff proves, so name what was actually checked and report the call as unverified where nothing checked it, since a guessed two-way door invites a reviewer to merge something nobody has walked back.

`implement` and `code-review` are untouched and their boundary is unchanged: a build still ends at a local commit and a review report. `pr` consumes that report when one is in front of it, but the report is a source rather than a requirement, so work that did not come from a build run gathers the same evidence itself and says which it has. Nothing is delegated, nothing runs in parallel, and no dependency is added.

`README.md` records twelve registered skills, adds `pr` to the Pi status table as model-invoked, and marks it **Implemented**: adapted and registered, but no PR body has been drafted with it here, so no claim of an exercised drafting run is made anywhere in this changeset. The maturity sentence that said all eleven were **Validated** and none sat in **Implemented** is reworded, since one now does. The `pr` docs page carries the fork's Pi banner, the Pi invocation, and a clarification that in Pi the draft is markdown text in the terminal until someone posts it, which makes a call tree, file tree, or shaped diff the safest of the six views here. `AGENTS.md` moves the `pi.skills` count from eleven to twelve; no other policy in it changed. The bucket README and the top-level promoted listing keep their `pr` entries unchanged, since both still describe its behaviour accurately.
