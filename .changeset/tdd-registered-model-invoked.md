`tdd` is now registered in this fork's `pi.skills` manifest, as the ninth skill. It stays model-invoked: its frontmatter carries no `disable-model-invocation`, so Pi advertises it by name, description and path in the agent's `<available_skills>` block and loads it by reading its `SKILL.md`, and the human can force it with `/skill:tdd`. Its `agents/openai.yaml` is unchanged, and carries no `policy` block, the same shape as the other model-invoked skills in this fork.

The methodology is upstream's and is preserved: tests verify behaviour through public interfaces, seams are the public boundaries tests live at, the seam-confirmation gate still stops before any test file exists, one seam and one test and one minimal implementation per cycle (vertical slices, not horizontal ones), red before green, no coupling to internals, mocks only at system boundaries, and refactoring is not part of the loop but the later review stage. `tests.md` and `mocking.md` are unchanged.

One instruction is adapted for Pi. Upstream's seam section said to call the Skill tool with `codebase-design` when the shape of an interface is in question. Pi has no Skill tool, and that skill is not in this fork's manifest, so the line now says to read `skills/engineering/codebase-design/SKILL.md` in the checkout as vocabulary, still only when the interface's shape is genuinely in question. The reference stays a reference, not a workflow: `codebase-design` is not registered, nothing launches it, and its `DESIGN-IT-TWICE.md` parallel-subagent pattern is out of scope in a fork that runs one session at a time. When the file is absent the skill reports that and continues with `tdd`'s own seam guidance rather than inventing a replacement methodology.

Two clarifications were added to the same file, both narrow. The seam gate now separates a seam already recorded as human-approved, which is reused without re-asking, from one that is inferred, proposed, or unapproved, which still needs the human's answer before any test is written; acceptance criteria name behaviour, not seams, so they are never approval on their own. The tautological anti-pattern now names where expected values come from when the work has a spec or ticket: its acceptance criteria and the commit-pinned spec, never from what the implementation currently returns.

`README.md` records nine registered skills, adds `tdd` to the Pi table as model-invoked, and marks it registered but not runtime-tested: no red → green cycle has run in this fork, so it joins the untested list. The tdd docs page carries the Pi banner, the Pi invocation, and a correction to upstream's claim that `codebase-design` must be installed. `AGENTS.md` moves the `pi.skills` count from eight to nine; no other policy in it changed. `codebase-design`, `code-review`, and `implement` stay out of the manifest, and the Claude plugin registration is untouched.
