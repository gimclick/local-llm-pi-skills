Pi's install route moves from the skills.sh fallback to Pi's own package install. No registration list moves: `package.json` → `pi.skills` still names twenty paths, ten user-invoked and ten model-invoked, each path unchanged, explicit and repo-relative, and the Claude plugin manifest is untouched with the promoted set still 27. `check-pi-registration` reports the same twenty before and after this change, and `check-plugin-version` still reports `plugin.json version is 1.3.1 (already in sync)`. What changed is the wording that tells a Pi user how to get the skills, in `.agents/install-block.md`, which owns the canonical wording, and in the README's "Get the skills" list.

The reason the route moves is what this fork is for. Upstream changes reach a Pi user through `main`, and the package clone is the surface that reads `main`. On 2026-10-28 the installed clone at `~/.pi/agent/git/github.com/gimclick/local-llm-pi-skills` was on `57745e2`, which carries the upstream sync PRs #24 and #25, while the skills.sh farm under `~/.agents/skills/` served this checkout instead. The clone is a clone of this fork, so it carries the fork's adapted copies and the upstream sync in one place, and `pi update git:github.com/gimclick/local-llm-pi-skills` is one command that moves the installed skills.

The same check corrected a claim in the install block. It said to prefer skills.sh to an agent's own repo installer "such as `amp skill add` or `pi install git:…`, because those also pull in `misc/` and `in-progress/`". That holds for the other installers and not for Pi. The clone carries `skills/misc/git-guardrails-claude-code` and `skills/in-progress/chief-of-staff`, and neither loads, because the package route reads the `pi.skills` manifest and loads only the names it declares. The Pi row and the Pi canonical block now say that, and `pi` is removed from the other-agents command comment so the two routes cannot be read as interchangeable.

The exclusivity note names the symptom a double install produces on Pi instead of only warning about it. Pi prints a `[Skill conflicts]` block at startup when two surfaces carry the same skill name, and keeps the first skill it discovers and skips the rest. On 2026-10-28 a 34-entry symlink farm under `~/.agents/skills/`, created by `npx skills add mattpocock/skills -a pi`, collided with the installed package clone: 19 names collided, the farm won every one, and the clone's copies were dead weight. The note tells Pi users to pick the package route and not to run the skills.sh command alongside it. Retiring the farm by renaming it to `~/.agents/skills.disabled` is one `mv`, and Pi scans `~/.agents/skills/` as a fixed path, so the sibling is not scanned.

One formatting fix rides along. `.changeset/grill-with-docs-registered-user-invoked.md` carried a top-level heading after the frontmatter; every other changeset in the folder is frontmatter followed by paragraphs, so the heading is removed to match. No skill implementation file changed in this changeset.
