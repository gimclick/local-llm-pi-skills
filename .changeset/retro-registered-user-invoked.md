All seven candidate categories keep their original `_Use when_` triggers: **Navigation** (a navigation pointer where the session struggled to find a file or a fact), **Automated checks** (read the repo's own check command first, its `package.json`/build-tool `lint`/`check` scripts and its CI workflow, so a check that already exists but sits unwired or silently broken is the finding rather than a reinvention; a repo with no guardrail at all, no pre-commit hook and no CI job running its lint/typecheck/test command, is itself a finding), **Coding standards** (classify the violation first: a mechanical one, a fixed syntactic pattern, a banned API, an import shape, or a file-location rule, gets a deterministic check in the repo's own linter, a new pre-commit hook, or a new CI job, whichever the language and existing guardrail make cheapest, and building the check is the default over writing the rule; `CODING_STANDARDS.md` is reserved for genuine judgement calls), **Global AGENTS.md** (steering that should move into standards or checks instead), **Tool economy**, **No-ops**, and **Information access**. The reference survives with them: all work goes through implementation and review, the implementation agent carries the most context pressure and the review agent the least, so a new standard goes where there is room to apply it, which is review, and never into an always-loaded instruction file, which is for navigation pointers and little else. What this fork adds is loading, evidence, and a boundary, not a workflow. Step 1's Claude Skill-tool call becomes Pi's explicit pattern: check `writing-for-agents` in the agent's `<available_skills>` block, read `skills/productivity/writing-for-agents/SKILL.md` in this checkout before any session evidence is read, and follow that file's own conditional pointer to `SKILL-MECHANICS.md` when the candidate being judged is a skill document. The load stays eager, which is upstream's decision and stays upstream here, because the reference carries the definitions of a no-op instruction and of a good skill, and those are the yardsticks the **No-ops** and **Skills** candidates are judged against; a retro that only reads and reports still needs them. A name that is not loaded is reported as a missing dependency and the run stops rather than judging the steering files with no yardstick. Nothing from the reference is restated inside `retro`, and `writing-for-agents` itself is untouched.

Session evidence is Pi's, not the model's memory. Upstream's default stands: the current session unless the user names another, which the user selects by path, by session ID, or from the `/resume` picker. A past session is read from its JSONL file, and a fresh session does not hold another session's conversation. The logs are large, so the skill identifies the selected session first, follows its actual entry structure (entries form a tree linked by `id`/`parentId`, and headers, tool results, and compaction entries are separate entry types rather than user or assistant messages), and searches by entry type, keyword, entry ID, or bounded range instead of loading a whole log into the model context. Observed stays apart from interpreted: a recorded tool call and its output are observations, a model's account of what it was doing and a compaction summary are interpretations, and a compaction summary can locate an event but is not proof of one. Reasoning that cannot be read is not reconstructed as evidence. A category the record does not support is reported as having no evidence rather than filled with a plausible finding, and every candidate names its source, with repository artifacts (committed diffs, test runs, the repo's own check scripts, CI workflows, hooks, steering files) used as corroboration where they apply.

The write boundary is now explicit rather than implied. `retro` writes nothing: no source code or project instruction edited, no other skill edited, no CI check or hook created or changed, no `CODING_STANDARDS.md` created, no Git configuration changed, no dependency installed, no commit or push, no issue or pull request opened or edited, and no external permission changed. It presents the candidates and stops for the human to pick, and a selected improvement is a separately authorized implementation task with its own review. A check that already exists is preferred over a duplicate, and a newly proposed blocking check is code like any other: run it against the project, including against changes that should pass, before it is allowed to block. A fork-specific rule sits with the Files reference: `CLAUDE.md` is upstream-controlled and must not be deleted, rewritten, or trimmed, and `AGENTS.md` is fork-local and harness-aware, so `retro` may name a no-op or a redundant instruction in either and recommend its removal or its move, but it edits neither, and it never proposes adding an instruction to an always-loaded file when a narrower surface the agent already reads would carry it. No new document is created to hold retrospective findings.

Execution is stated rather than assumed: one selected session or one clearly bounded work episode at a time, nothing delegated, nothing in parallel or in the background, on this fork's single inference slot. No other skill invokes `retro`: it stays an independently invoked workflow and is not a step that `implement`, `code-review`, `pr`, or `triage` reaches for.
