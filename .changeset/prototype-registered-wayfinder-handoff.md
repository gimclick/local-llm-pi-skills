`prototype` is now registered in this fork's `pi.skills` manifest, as the seventh skill. Its files are upstream's, unchanged: the two branches (a self-contained logic demo, or structurally different UI variants on one route) and the rules about disposable code, visible state, and human evaluation all still read as they did upstream. It stays model-invoked, so Pi advertises it in the agent's `<available_skills>` block and loads it by reading its `SKILL.md`.

`wayfinder` gains a `Prototype tickets` section, so a `wayfinder:prototype` ticket has a methodology to load rather than a route that names a skill the manifest never enabled. The skill is loaded in the foreground parent session, never delegated to a subagent and never run beside another delegated run: the ticket is HITL, and a child cannot hold the exchange it needs. The prototype answers the question that ticket's body asks, and the ticket owns the artifact: it is committed to a throwaway `prototype/<name>` branch, pushed with no pull request and never merged into the default branch, and the ticket records the branch, the artifact path inside it, and the commit identifier. No implementation issue is assumed, because a wayfinder map has none. Branching reads the Git state first and works in an isolated worktree or a fresh branch, so it cannot overwrite an existing branch, discard unrelated working-tree changes, or move the checkout the map's other work lives in.

The human's verdict is what resolves a prototype ticket. The agent shows the artifact and puts the ticket's question to the human against it; it does not pick a winning UI variant, does not decide that the prototype has answered, and leaves the ticket open and unresolved until a verdict arrives. Only then does the resolution comment record the question and the settled decision in the human's own words, the ticket close, and the map gain its one-line gist and link. The map stays an index pointing at that decision.

Upstream `prototype` folds validated code into the real codebase once a variant wins. Inside a map that is out of bounds, and the skill now says so: the demonstration and the confirmed decision are what the map keeps, and nothing is folded into production or started as implementation from the session that resolved the ticket. Standalone `prototype`, reached for outside a map, keeps upstream's promotion behaviour.

`README.md` records seven registered skills, adds `prototype` to the Pi table, and describes the handoff. The prototype and wayfinder docs pages carry the Pi banner, the branch and approval behaviour a map imposes, and the distinction between a registered skill and a tested one: `prototype` is registered and has never been exercised in this fork, so it stays on the untested list.
